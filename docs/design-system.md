# Steeefanie Personal Site 设计规范

> 版本：2.44
> 状态：现行设计说明
> 更新日期：2026-10-17
> 适用范围：主页、随笔、项目、食谱、长文详情页及轻量工具页面

## 1. 文档定位

本文件记录 Steeefanie Personal Site 当前已实现的视觉、排版、布局、组件、交互、响应式和可访问性规则。项目与食谱的公开路由、页面目录和内容集合分别使用 `projects`、`recipes`。运行时数值以代码为准，文档随实现同步更新。

规范综合参考：

- Geist 的令牌化方法、排版尺度、4px 间距体系和克制的开发者界面风格；
- Apple Human Interface Guidelines 的层级、协调、一致性、适配、触控、动效和可访问性原则；
- 本项目“个人开发者主页 + 技术博客 + 项目案例”的实际信息架构；
- 当前 Astro、Markdown / MDX、三语言切换、搜索筛选和深浅主题实现。

参考内容用于排版、间距、组件状态和可访问性设计。

## 2. 设计目标

### 2.1 产品定位

网站首先是内容载体，其次才是个人品牌展示。核心目标是让访问者快速完成以下任务：

1. 了解 Steeefanie 的关注方向；
2. 浏览技术随笔和开发记录；
3. 查看项目背景、实现过程和使用方法；
4. 查阅菜谱、鸡尾酒配方和制作备注；
5. 在简体中文、台湾繁体、英文、深浅主题和不同设备间获得一致体验。

### 2.2 体验关键词

- 现代；
- 克制；
- 安静；
- 清晰；
- 内容优先；
- 技术感适度；
- 可长期维护。

### 2.3 核心原则

#### 内容优先

标题、摘要、正文和项目说明是视觉中心。装饰、插画、动效和容器不得压过内容。

#### 层级明确

全站文字共用 `--font-size-unit` 响应式基准：宽屏为 1rem，窄屏平滑缩至最低 0.94rem；固定字号按该基准设置比例，页面标题与正文二至四级标题另设连续缩放范围，始终保持字号层级。正文、简介、标签、导航、目录、搜索、图标名称、代码和工具页文字均纳入，使用 em 或 inherit 的子级随父级缩放。根字号和布局用 rem 不随这项规则改变。

通过字号、字重、间距、对齐和明度建立层级。颜色仅作为辅助，不单独承担状态表达。

#### 控制层与内容层分离

导航、语言切换和主题切换属于控制层，可以使用半透明和模糊；文章、项目和正文属于内容层，使用稳定背景，不使用大面积玻璃效果。

#### 一致而非完全相同

主页、随笔、项目和食谱共享基础视觉语言，但允许根据内容类型形成适当差异。随笔强调连续阅读，项目强调技术标签和实现过程，食谱强调材料、步骤、用时和份量。

#### 适配优先

布局必须适应屏幕宽度、字体缩放、语言长度和输入方式变化，而不是只适配某个设备截图。

#### 可访问性默认开启

键盘操作、焦点样式、减少动态效果、语义 HTML、合理对比度和足够大的触控区域贯穿现有页面和组件。

## 3. 品牌与颜色

### 3.1 不可变品牌基准色

标准品牌色固定为：

```text
RGB: 99, 6, 95
HEX: #63065F
```

浅色主题的品牌色为 `#63065F`，深色主题为 `#C979C4`。

品牌基准色主要用于：

- `Steeefanie` 站点名称；
- 重要品牌标记；
- 浅色背景上的链接和当前导航；
- 主要操作的实色背景；
- 少量标签、代码强调和装饰细节。

### 3.2 主品牌色与深色备用品牌色

浅色主题使用主品牌色；深色主题使用为可读性设定的备用品牌色。每种主题内部只允许一个紫色色值：

```css
:root {
  --brand: #63065f;
  --brand-interactive: #63065f;
  --brand-readable: #63065f;
  --brand-strong: #63065f;
  --brand-soft: rgba(99, 6, 95, 0.1);
  --focus: #63065f;
}

:root[data-theme='dark'] {
  --brand: #c979c4;
  --brand-interactive: #c979c4;
  --brand-readable: #c979c4;
  --brand-strong: #c979c4;
  --brand-soft: rgba(201, 121, 196, 0.16);
  --focus: #c979c4;
}
```

使用规则：

- 浅色主题中，任何紫色文字、图标、下划线、焦点环和状态标记都严格使用 `#63065F`；
- 深色主题切换时，上述所有品牌与交互用途全局替换为备用色 `#C979C4`，不得混用主品牌色；
- 需要弱背景时，只能以当前主题生效的品牌色增加透明度，不建立新的实色紫色；
- 大面积品牌实色按钮使用当前主题的 `--brand`，文字使用柔和的近白色；
- `#C979C4` 与深色页面、普通表面和抬升表面的对比度均达到普通文字WCAG AA底线；当前状态仍应同时使用下划线、字重、圆点或 `aria-current` 等非颜色信号。

品牌图标使用同一中心对称 S 形标志：浅色主题固定为 `#63065F`，深色主题固定为 `#C979C4`。标签页图标和导航字标只使用透明底版本，并跟随网站实际主题而不是仅跟随操作系统主题。

### 3.3 浅色主题

浅色主题使用不带色相倾向的中性灰。页面底色为浅灰，内容表面和顶部导航可使用纯白；品牌紫色不得混入页面、表面、代码块或导航底色。

```css
:root {
  --page: #fafafa;
  --surface: #ffffff;
  --surface-raised: #ececec;
  --surface-soft: #f3f3f3;
  --text: #222222;
  --muted: #888888;
  --border: #d9d9d9;
  --code-bg: #1f1f1f;
  --code-text: #f0f0f0;
  --header-bg: rgba(255, 255, 255, 0.64);
  --focus: #63065f;
}
```

### 3.4 深色主题

深色主题同样使用无色相倾向的中性灰，不使用大面积纯黑。页面保持深灰，导航公共层比页面更深。

```css
:root[data-theme='dark'] {
  --page: #111111;
  --surface: #1d1d1d;
  --surface-raised: #262626;
  --surface-soft: #1a1a1a;
  --text: #eeeeee;
  --muted: #888888;
  --border: #333333;
  --code-bg: #0d0d0d;
  --code-text: #f0f0f0;
  --header-bg: rgba(8, 8, 8, 0.64);
  --brand: #c979c4;
  --focus: #c979c4;
}
```

深浅主题不是简单反相。每个主题分别保证文字、边框、代码块和控制层具有稳定层次。

### 3.5 当前颜色对比度

下表按现行令牌计算，列出页面底色上的文字组合：

| 前景与背景 | 对比度 | 当前用途 |
|---|---:|---|
| `#222222` / `#FAFAFA` | 15.24:1 | 浅色正文 |
| `#888888` / `#FAFAFA` | 3.40:1 | 浅色辅助文字 |
| `#63065F` / `#FAFAFA` | 11.68:1 | 浅色品牌文字 |
| `#EEEEEE` / `#111111` | 16.28:1 | 深色正文 |
| `#888888` / `#111111` | 5.33:1 | 深色辅助文字 |
| `#C979C4` / `#111111` | 6.31:1 | 深色页面品牌文字 |
| `#C979C4` / `#1D1D1D` | 5.63:1 | 深色普通表面品牌文字 |
| `#C979C4` / `#262626` | 5.06:1 | 深色抬升表面品牌文字 |

焦点、当前状态和错误信息同时使用语义属性或形态表达。

### 3.6 状态颜色

当前站点以阅读为主，不建立大量彩色状态体系。项目不区分“已发布、实验、进行中”等状态，也不显示状态圆点；导航当前项、语言选择、筛选选中等交互状态必须同时依靠语义属性或形态变化表达，不能只依靠颜色。

## 4. 字体与排版

### 4.1 字体栈

```css
--font-sans-en: "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI", Arial, sans-serif;
--font-sans-zh: "Noto Sans SC", "Source Han Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif;
--font-sans-zh-tw: "Noto Sans TC", "Source Han Sans TC", "PingFang TC", "Microsoft JhengHei", sans-serif;
--font-mono: "JetBrains Mono", "SFMono-Regular", Consolas, monospace;
```

规则：

- 中文和英文正文均使用无衬线字体；
- 每种语言只使用一套主字体栈；
- 代码和等宽数据使用 `--font-mono`；
- 标签的拉丁字符优先使用等宽字体；简体中文标签必须在通用 `monospace` 之前回退到 `Noto Sans SC / Source Han Sans SC / PingFang SC / Microsoft YaHei`，台湾繁体对应回退到 `Noto Sans TC / Source Han Sans TC / PingFang TC / Microsoft JhengHei`，避免 Windows 因 Consolas 缺少中文字形而落入宋体；
- 在线字体加载失败时必须有可靠系统回退。

### 4.2 字重

界面主要使用三档字重：

```text
400 Regular：正文、摘要、说明
500 Medium：导航、标签、次级标题、按钮
600 Semibold：页面标题、章节标题、重点内容
```

### 4.3 排版令牌

字号以 `U = var(--font-size-unit)` 为基准，`U = clamp(0.94rem, 0.92rem + 0.1vw, 1rem)`。以下为当前使用的字号和行高：

| 样式／令牌 | 字号 | 行高 | 用途 |
|---|---|---|---|
| `--font-size-home-display` | `clamp(2.7U, 2.2U + 2.2vw, 4U)` | 1.06 | 首页主标题 |
| `--font-size-home-section-title` | `clamp(1.35U, 2.4vw, 1.85U)` | 1.25 | 首页区块标题；留言标题行高 1.2 |
| `--font-size-section-title` | `clamp(1.55U, 3vw, 2.2U)` | 1.25 | 内容详情标题；工具页标题行高 1.2 |
| `--font-size-prose-h2` | `clamp(1.3U, 2.35vw, 1.72U)` | 1.3 | 正文二级标题；评论标题行高 1.2 |
| `--font-size-prose-h3` | `clamp(1.15U, 1.85vw, 1.35U)` | 1.3 | 正文三级标题 |
| `--font-size-prose-h4` | `clamp(1.05U, 1.5vw, 1.12U)` | 1.3 | 正文四级标题 |
| `.prose` | `1.02U` | 1.72；英文 1.66 | 长文正文 |
| `.article-deck` | `1.08U` | 1.62 | 详情简介 |
| `.article-meta` | `0.78U` | 1.62 | 详情日期、类别、用时、份量和标签 |
| `.item-title` | `clamp(1.25U, 2.2vw, 1.72U)` | 1.25 | 内容列表名称 |
| 食谱图标视图名称 | `1U` | 1.5 | 图标下方名称 |
| `.prose pre` | `0.86U` | 1.55 | 代码块 |

`U` 是排版说明中的简写，代码使用 `calc(var(--font-size-unit) * 比例)`。普通标签、按钮、目录和工具页说明均以相同比例基准设置字号；使用 `em` 或 `inherit` 的文字跟随父级。根字号和布局用的 `rem` 保持独立。

大标题字距允许收紧，正文不使用负字距：

```text
home-display（英文）：-0.04em
home-display（中文混排）：-0.025em
home-section-title / article-title：-0.035em
正文二至四级标题：-0.028em
正文与元信息：normal
```

负字距不是装饰效果，也不应普遍用于正文。大号拉丁字母的字偶间距和字形两侧留白会随字号同步放大，保持默认字距时容易显得松散，因此展示标题允许轻微收紧，以恢复词形整体性和稳定的视觉密度。中文方块字本身占据较完整的字面空间，只需更弱的负字距；中英文混排不得直接套用强拉丁字距，否则中文笔画和标点会显得拥挤。字距必须随字号和文字系统分别校准，正文、摘要与元信息保持正常字距。

随笔、项目、家常菜和面食详情的顶层正文段落使用固定 `text-indent: 2rem`。鸡尾酒详情普通段落、页面导语、摘要、列表、标题、引用、图注、控件及表格无首行缩进。

主页介绍、“关于我”正文和随笔、项目、食谱详情页中的正文段落均使用两端对齐，末行保持左对齐。中文使用字符间调整，英文使用词间调整并按当前 `lang` 启用自动断词；标题、摘要、列表说明、元信息、按钮和代码块不使用两端对齐。

### 4.4 阅读宽度

- 全站宽容器：1120px；
- 文章正文：680–740px；
- 中文正文优先保持较短行长；
- 英文正文建议每行约 60–80 个字符；
- 代码块和表格可在正文容器内部横向滚动，不扩大页面宽度。

### 4.5 文本缩放

布局必须在以下情况下保持可读：

- 浏览器缩放 200%；
- 320px 窄屏；
- 中英文长标题；
- 系统较大字体；
- 日期和标签长度增加。

重要内容不得通过固定高度裁切。导航和控件不得因文字变长而互相覆盖。

## 5. 间距体系

### 5.1 基础尺度

采用 4px 基础单位：

```text
space-1   4px
space-2   8px
space-3  12px
space-4  16px
space-6  24px
space-8  32px
space-10 40px
space-12 48px
space-16 64px
space-20 80px
space-24 96px
```

所有新增间距原则上从该尺度选择。确有排版需要时可以使用其他 4px 倍数，但不新增 17px、27px、42px、54px 等缺少体系依据的值。

### 5.2 使用节奏

- 4–8px：图标和文字、同组元信息；
- 12–16px：标题与摘要、相邻控制项；
- 24–32px：列表项内部、内容小组之间；
- 40–48px：标题区与列表、章节内部；
- 64–96px：首页大区块和页面主章节。

间距优先用于表达关系：越相关越接近，越独立越分开。

首页当前纵向间距如下：

```text
页面顶部 → Hero 内容：32px
Hero 标题 → 介绍文字：32px
Hero 内容 → 在线服务标题：64px（40px + 24px）
在线服务标题 → 图标内容：32px
在线服务内容 → 最近更新标题：80px（40px + 40px，首页最大的相邻模块间距）
最近更新标题 → 本区块内容：24px
“最近更新”上一条说明文字 → 下一条栏目标签：桌面端28px（12px + 4px + 12px），800px及以下32px（14px + 4px + 14px）
“最近更新”上一条说明文字 → 下一条标题：桌面端约50px，800px及以下约54px（另含栏目标签约16px行盒及6px下间距）
“最近更新”内容 → 页脚文字：56px（32px + 24px）
```

首页以及随笔、项目、食谱列表项采用同一套反向密度补偿：宽屏下说明文字通常不换行，使用12px上下内边距；800px及以下内容更容易换行，使用14px上下内边距。各页面的列宽由相应布局规则控制。计算首页“最近更新”的视觉间距时必须计入栏目标签的行盒和下间距，不得只相加列表项内边距与列表间隙。

首页最近更新、随笔和项目列表采用流动双列结构：正文列吸收剩余空间，元信息列占容器约三成且不小于190px，两列间距为38px；800px及以下改为单列。食谱使用图标视图或带配图的列表视图，尺寸见 6.7。

## 6. 布局与响应式

### 6.1 容器

```css
--content-wide: 1120px;
--content-reading: 740px;
--page-gutter: 30px;
```

页面内边距：

```text
桌面：左右各30px
平板：左右各30px
手机：左右各30px
```

宽容器和阅读容器统一使用30px视口边距；组件内部不得再次添加同等水平内边距，避免留白叠加。

### 6.2 项目断点

为保持与现有实现一致，使用以下行为断点：

```text
Compact：≤ 720px
Medium：721–800px
Wide：> 800px
```

断点用于内容需要发生变化的位置，不按具体设备型号增加断点。

验收视口至少包括：

```text
320×568
390×844
768×1024
1024×768
1440×900
```

### 6.3 对齐

- 导航内容与页面宽容器使用同一左右基准；
- 正文详情页使用独立阅读容器；
- 文章和项目列表的标题、摘要、元信息保持稳定列关系；
- 移动端改为单列，元信息左对齐；
- 不使用无意义的居中对齐长正文；
- 三语言切换后整体基线和导航宽度保持稳定；四个导航项与搜索、语言、主题三个图标按钮使用同一44px控制高度。三个图标允许在命中区域不变的前提下视觉下移1px，以补偿图标与文字字面的光学中心差异。
- `Steeefanie` 是固定拉丁字标，其中首字母 `S` 由透明底品牌 SVG 替代，后续文字固定为 `teeefanie`。标志使用16.5×24px可见裁切框、27×27px居中图像，后续文字左外边距为-2px；完整链接的无障碍名称仍为 `Steeefanie`。文字统一使用拉丁字体栈、1 倍响应式字号基准、600 字重和 1 倍行高，不继承中文语言字体栈，随全站字号基准缩放。

### 6.4 首页布局

首页顺序固定为：

```text
欢迎语与个人简介
在线服务
最近更新（随笔、项目、食谱各取最新1条，共3条，按发布日期重新排序）
页脚
```

- 首页说明分别自然引导至随笔、项目和食谱，中文使用“技术笔记、踩坑经历、碎碎念”“做过的菜、揉过的面、调过的酒”等生活化表达；英文采用自然意译，并使用 `dough I’ve kneaded` 表达发面、馒头和发糕一类面食语境，不写作 `noodles`；
- “关于我”正文不使用首行缩进；
- “关于我”使用独立的中性抬升表面，其下方设置联系方式行：左侧显示纯文本 `Contact: taichieh3@gmail.com`，其左边线距卡片左边12px，与12px圆角曲线和底边直线的交界点对齐；右侧GitHub图标保留外部链接和明确的无障碍名称；
- “在线服务”优先于内容更新列表，展示可直接使用的轻量工具入口；当前单个服务使用低密度图标入口，使用图标和名称展示；

### 8.2 材质与毛玻璃

半透明模糊只用于顶部公共材质层和临时控制层：

```css
backdrop-filter: blur(20px);
```

规则：

- [Apple HIG Materials](https://developer.apple.com/design/human-interface-guidelines/materials) 使用 `ultraThin / thin / regular / thick` 等语义材质而非固定网页像素区间；本站导航文字量介于 thin 与 regular 的使用场景之间，采用偏清透配置；
- 参考 [Apple WWDC25「What’s new for the spatial web」](https://developer.apple.com/videos/play/wwdc2025/237/)示例采用的 `blur(20px)` 以及0.8至0.5半透明底色，本站保持 `blur(20px)`，将底色透明度取为偏清透的0.64；
- 浅色公共层以纯白为色源，使用 `rgba(255, 255, 255, 0.64)`，合成后比 `#FAFAFA` 页面更亮；深色公共层使用 `rgba(8, 8, 8, 0.64)`，比 `#111111` 页面更深；
- 公共层不提高透过内容的饱和度，避免品牌紫色污染中性底色；
- 页面、内容表面、抬升表面、代码块、灰色边界和导航底色都必须使用 R=G=B 的中性灰；品牌紫色只用于品牌与交互语义；
- 背景必须有足够不透明度保证文字可读；
- 导航和展开面板由同一个公共材质层承载，导航自身保持透明；
- 导航隐藏时公共材质层高度收缩至 0；搜索或菜单面板打开时导航可见；
- 不添加明显投影；

### 8.3 滚动行为

- 向上滚动超过阈值后导航重新显示；

- 微小滚动不反复触发；

状态规则：

- hover 只能作为辅助，功能不能依赖 hover；
- active 必须有即时反馈；桌面和iPad的单行列表可使用轻微位移，720px及以下的多行列表不得改变横向内边距、缩放或宽度，只通过严格的主题色变化反馈，避免触摸后重新换行；
- focus-visible 必须清晰可见；
- disabled 不响应操作，并提供视觉和语义状态；
- 桌面持久导航的当前页面不能只改变颜色，应增加下划线；临时移动菜单允许使用主题交互色配合 `aria-current` 表示当前页面。
- 搜索、语言、主题和菜单图标按钮悬停时保持透明背景，只将图标变为主题交互色；

### 9.3 焦点样式

当前公共焦点样式为：

```css
:focus-visible {
  outline: 2px solid var(--focus);
  outline-offset: 4px;
}
```

## 10. 语言切换

语言控件使用地球图标，菜单固定显示：

```text
简体中文
繁體中文
English
```

要求：

- 地球图标是一个至少44×44px的按钮；
- 简体中文为兜底语言；语言菜单文字靠右排列，手机端文字右边缘与移动导航保持同一约45px基准线；
- 简体中文、台湾繁体和英文分别使用 `/zh-cn/`、`/zh-tw/`、`/en/`；三种语言均生成独立静态页面，每个页面只输出当前语言的界面和正文；
- 当前语言不显示勾选，只使用主题交互色表示；语言选项使用真实链接，并以 `aria-current="page"` 表示当前页面；
- 点击后进入同一逻辑内容的目标语言地址，列表查询参数继续保留；长文优先按对应标题序号恢复阅读位置，其他页面按滚动进度恢复；
- `<html lang>`、页面标题、描述、日期、搜索结果、筛选标签和辅助技术标签在构建时即与当前路由语言一致，不依赖客户端切换后修正；
- 明确的语言 URL 是页面语言的唯一来源，不根据 Cookie 或浏览器偏好改写已经带语言前缀的地址；
- 裸域 `/` 只作为语言分流入口，依次读取用户主动选择后写入的第一方 Cookie `steeefanie_locale`、浏览器语言，无法匹配时进入 `/zh-cn/`；不使用 IP 判断语言；
- Cookie 仅保存 `zh-cn | zh-tw | en`，作用域为全站，使用 `SameSite=Lax`，有效期一年；浏览器自动判断结果不得写入 Cookie，只有用户主动点击语言选项时才更新；
- 语言类型固定为 `zh-CN | zh-TW | en`，URL 前缀分别为 `zh-cn`、`zh-tw` 和 `en`；
- 台湾繁体必须使用独立内容文件和台湾常见术语，不在运行时自动转换；
- 搜索结果、导航、上一篇/下一篇、在线工具和项目互链必须留在当前语言；不得因点击站内链接退回简体中文。

三语言通用界面文案集中维护；内容以同 slug 的三份文件配对，任一语言缺失时不进入正式列表、详情路由和搜索索引。

## 11. 主题切换

### 11.1 控件

- 使用太阳短射线与右下月相切口组合图标，使用代码内 SVG 绘制；
- 月相主体不得添加完整圆形描边；由右下方月牙的弧线、人眼视觉补齐和外围射线共同建立圆形感；
- 图标使用 `currentColor`，不得嵌入固定黑白位图或依赖主题背景色切口；
- 图标按钮具有动态 `aria-label`；
- 图标视觉尺寸约 18–20px；
- 按钮命中区域至少 44×44px。

### 11.2 初始化优先级

```text
1. localStorage 已保存主题
2. prefers-color-scheme
3. 浅色主题
```

主题初始化应在页面绘制前尽早执行，避免闪白或闪黑。

### 11.3 扩散动画

- 切换开始时必须完整保留旧主题，不得先将整个页面立即切换到新主题；
- 浏览器先捕获旧主题，再提交新主题状态；
- 新主题作为新视图，从当前可见主题图标的几何圆心以圆形裁剪区域逐渐显现；
- 圆扩散到哪里，哪里才显示新主题；圆外区域在动画完成前继续显示旧主题；
- 圆心必须读取 SVG 图标的实时边界中心，不使用整个 44px 按钮命中区域的中心代替；
- SVG 中心坐标必须换算为根视口宽高内的百分比，再传给圆形裁剪；不得直接把页面 CSS 像素作为快照伪元素的局部坐标，以免桌面快照发生缩放时圆心偏移；
- 半径覆盖最远视口角点；
- 覆盖半径与圆心百分比基于同一冻结根快照视口；宽度必须使用包含经典滚动条区域的 `window.innerWidth`，不得使用会少一个滚动条宽度的 `documentElement.clientWidth`；快照组固定宽高且 `transform: none`；
- 根元素使用 `scrollbar-gutter: stable` 稳定保留经典滚动条沟槽，避免 Windows Chrome 在快照层与真实页面之间出现横向抖动；
- 旧主题快照固定 `opacity: 1`、`filter: none`，不得参与淡出、压暗、缩放或透明度动画；仅裁剪新主题快照；
- 视觉节奏按半径匀速，使用 `r(t)=Rt` 的线性关键帧；时间25%、50%、75%时半径分别达到覆盖半径的25%、50%、75%；
- 总时长按覆盖半径计算为 `clamp(280ms, radius / 3.3, 440ms)`，手机保持快速，大屏增加有效帧数；
- 圆形裁剪动画必须预先声明在 `::view-transition-new(root)` 上，使其在新视图图层生成时同步启动；
- 不得先将 View Transition 动画全部置空，再等待 `transition.ready` 后通过 JavaScript补挂动画，以免首次加载时产生伪元素生命周期竞态；
- 根快照组允许关闭默认几何插值，但必须明确冻结其视口宽高和变换，不能让浏览器在新旧几何之间缩放；
- 优先使用 View Transitions API 保证背景、文字、边框和控件同步切换；
- 不支持 View Transitions 时降级为短暂淡出、提交主题、再淡入，不允许出现突兀闪白或闪黑；
- 不引发布局跳动；
- 快速连续点击必须加锁或合并；
- 不支持高级动画时降级为短暂渐变；
- 主题图标在扩散期间保持位置和姿态稳定，不叠加旋转动画；
- `prefers-reduced-motion: reduce` 时取消扩散。

该动画是主题状态变化反馈的特例，不作为其他页面大范围使用动画的依据。

## 12. 动效规范

### 12.1 时间令牌

```css
--motion-fast: 150ms;
--motion-standard: 200ms;
--motion-overlay: 300ms;
--motion-theme: 360ms; /* 动态时长的中间参考值 */
```

### 12.2 使用范围

| 场景 | 建议时长 |
|---|---:|
| 链接颜色、按钮背景 | 100–150ms |
| 按下反馈 | 100–140ms |
| 导航下划线 | 150–180ms |
| 导航显隐 | 200–220ms |
| 普通浮层 | 200–300ms |
| 主题圆形扩散 | 280–440ms，半径线性 |

### 12.3 原则

- 动效用于说明状态、层级或操作结果；
- 不添加持续循环和无意义背景动画；
- 不使用视差、大面积漂移和强烈弹跳；
- 不依赖动画传递唯一重要信息；
- 减少动态效果时优先使用颜色变化、淡入淡出或直接切换；
- 滚动监听使用被动监听和 `requestAnimationFrame`。

## 13. 列表与内容组件

### 13.0 列表筛选

- Blog 与 Projects 不提供列表筛选；Recipes 仅提供家常菜/面食/鸡尾酒类别单选筛选；
- 筛选值使用稳定类别枚举，不使用本地化显示文字作为 URL 值；
- 食谱类别筛选的 hover 和选中态使用主题色文字与1.5px底部短线，不使用胶囊、圆角矩形背景或选中底色；键盘焦点环不受影响；
- 筛选状态写入 URL 查询参数，并在刷新、前进后退和分享链接后恢复；
- 无结果时按当前语言显示空状态和“清除筛选”；
- 食谱筛选只显示“全部、家常菜、面食、鸡尾酒”四个选项，不显示“类别”等可见标题；筛选组仍保留仅供辅助技术读取的隐藏图例；四个选项的字号与同页文章摘要一致，桌面、iPad 和手机均使用 1 倍响应式字号基准并始终保持一行；选项间隔固定6px，按钮左右内边距固定11px，不随视口宽度收紧。空间不足时仅筛选行可横向滚动，不引起页面级横向滚动。

### 13.1 列表分页

- Blog、Projects 和 Recipes 列表每页最多显示20条，超出后显示上一页、页码和下一页操作；
- 页码写入 `?page=N`，第1页不保留冗余 `page=1`；刷新、前进后退和分享链接后应恢复当前页；
- Recipes 先按类别筛选，再对筛选结果分页；更换类别或清除筛选时回到第1页，筛选参数与页码参数可同时存在；
- 内容不足20条或筛选无结果时隐藏分页控件；越界、非数字或非正整数页码自动归一到有效页；
- 分页不使用胶囊、圆角矩形背景或分割线；当前页使用主题色文字和底部短线，方向按钮在边界页显示禁用状态。
- 从详情页点击“返回随笔／项目／食谱”时，恢复当前标签页内相应语言列表最近的筛选、页码与滚动位置；状态使用 `sessionStorage` 保存，不跨浏览器会话持久化。没有列表访问记录或存储不可用时，返回默认列表；普通导航进入栏目不强制恢复旧位置。
- 支持 Navigation API 时，只有前一条历史记录与目标列表完整地址一致才使用原生后退；其他情况按保存的列表地址导航，并在筛选完成及 `pageshow` 后恢复滚动位置，不误退到章节锚点或其他文章。

### 13.2 博客列表项

必须包含：

- 标题；
- 摘要；
- 发布日期；
- 阅读时间；
- 标签。

样式要求：

- 标题为主要视觉元素；
- 摘要使用次文字色；
- 元信息使用 `meta` 令牌；
- 上下使用留白形成节奏，不绘制常驻灰色分割线；
- hover 可轻微水平位移或改变标题颜色；
- 不增加厚重卡片背景和明显阴影。

### 13.3 项目列表项

必须包含：

- 项目名称；
- 一句话说明；
- 更新时间；
- 技术栈。

项目列表和详情的本地化日期均显示年、月、日，不省略日期中的“日”。

### 13.4 标签

- 使用等宽字体或较小无衬线字体；
- 普通标签不制作大胶囊；
- 标签之间保持 8–12px 间距；
- 标签颜色不得压过标题；
- 所有标签统一添加 `#` 前缀；技术名称按独立标签展示，例如 `#Astro #TypeScript #Tailwind #CSS`，不合并为 `#Tailwind CSS`；
- 标签文本本身不添加首尾空格；多语言标签容器和普通标签容器统一使用 CSS `gap` 产生间距，避免文本空格与布局间距叠加；
- 标签过多时自然换行，不横向撑破页面。

## 14. 长文排版

### 14.1 结构

Blog 详情页顺序：

```text
返回入口
标题
摘要
日期 / 更新时间 / 标签 / 阅读时间
正文
上一篇 / 下一篇
```

详情标题必须读取内容 frontmatter 的 `title` 并由统一模板输出；Markdown / MDX 正文不得重复书写一级标题，也不得在单篇内容中覆盖标题字号。详情标题统一使用 `--font-size-section-title`；首页区块标题使用独立的 `--font-size-home-section-title`，两者不得混用。

详情元信息统一字号与行高，日期、阅读时间、类别和标签按文字基线对齐，类别圆点在对应行盒中居中。上一篇/下一篇使用显式左右插槽：上一篇固定左列，下一篇固定右列；缺少任一方向时不渲染空占位，720px及以下统一为单列左对齐。

详情页头上下内边距为 38px、26px；返回入口至标题 12px，标题至简介 12px，简介至元信息 16px。正文区域上下内边距为 24px、70px；首个正文元素取消上外边距。食谱图文布局见 6.7。

Project 详情页顺序：

```text
返回入口
项目名称
一句话说明
时间 / 技术标签
正文
可选 Demo / Repository / Download
```

Recipe 详情页顺序：

```text
返回入口
食谱名称
一句话说明
菜谱/鸡尾酒类别 / 制作时间 / 份量 / 标签
推荐杯型或器具说明（有内容时）
材料
做法
提示或调整说明（有内容时）
上一篇 / 下一篇
```

### 14.2 正文

- 中文正文行高 1.72；
- 英文正文行高 1.66；
- 中英文正文段落均两端对齐且末行左对齐；英文启用自动断词，避免过大的词间空白；
- 随笔、项目、家常菜和面食的顶层正文段落使用固定 `2rem` 首行缩进；鸡尾酒正文、列表、引用、图注和表格无首行缩进；
- 有序列表必须显式使用十进制序号，无序列表必须显式恢复圆点，不能依赖浏览器在 CSS Reset 之前的默认样式；
- 标题层级必须连续、清晰；
- 段落之间通过间距区分；
- 链接使用品牌色和下划线；
- 引用使用细品牌色左边框；
- 表格在正文容器内水平居中，表格单元格文字居中且无首行缩进；超出阅读宽度时只在表格容器内部横向滚动；
- 图片必须有 `alt`；
- 大图避免阻塞首屏；正文图廊中的非首屏图片使用懒加载。

### 14.3 代码

- 使用等宽字体；
- 背景与正文形成清晰但柔和的层次；
- 横向溢出时只滚动代码块；
- 不使用过度花哨的语法主题；
- 行内代码与代码块有明确区别；
- 代码不得包含真实密钥、Token、密码或个人敏感路径。

### 14.4 文章目录

- 随笔和项目详情页在正文包含至少3个二级或三级标题时显示目录入口；食谱详情页不显示目录；
- 目录入口固定在左上角：收起时为44×44px圆形按钮，图标使用左侧三个圆点、右侧三条横线的列表符号；展开时同一表面由圆形过渡为圆角矩形，图标同步切换为关闭符号，并与“目录”文字在同一水平中线上；
- 主页“关于我”使用 `--surface-soft`：浅色为 `#F3F3F3`，深色为 `#1A1A1A`；目录以该令牌的 82% 不透明度为底色，使用 20px 背景模糊；
- 顶部导航显示时目录位于导航下方，导航向上收起时目录同步移至页面顶部，四周始终保留页面间距，不形成贴边断口；目录高度跟随当前语言的实际内容，只在内容超过视口可用高度时延伸至下边界并在内部滚动；
- 目录收录二级、三级标题，三级标题使用缩进区分层级；当前章节同时使用品牌色文字和左侧标记，不仅依赖颜色表达状态；
- 展开后根据实时几何空间判断布局，不以触摸或鼠标输入类型判断：剩余区域能够容纳原正文阅读宽度及左右页边距时，整个文章区域移入右侧剩余空间并居中；空间不足时目录覆盖在页面上，文章位置保持不变；
- 点击章节后立即定位，不使用平滑滚动；覆盖模式在点击正文、滚动正文或选择章节时关闭目录，并列模式保留目录；视口或目录宽度变化时实时重新判断模式；
- 目录默认宽度依据当前语言标题的实际字体宽度计算。将标题宽度从短到长排序，按最近秩法取P80；最长标题不超过P80的1.2倍时按最长标题计算，否则按P80的1.2倍计算，再加固定内边距与层级空间，并限制在260—380px；
- 用户可通过面板右边缘使用鼠标、触控笔、触摸或键盘调整宽度，手动宽度限制在240—440px并本地保存；手动值优先于自动值，语言切换不覆盖；恢复自动宽度后重新按当前语言计算；
- 窄视口只临时压缩实际显示宽度，不覆盖用户保存的手动值，视口恢复后继续使用原值；
- 移动端地址栏伸缩等仅改变可视高度的 `resize` 不重新测量目录宽度，避免收起状态的圆形入口短暂横向展开；
- 初始化、字体加载和宽度变化时，只测量目录内部列表，不临时改变圆形面板的宽高或位置，避免首次进入详情页时出现收缩动画；
- 目录内部列表始终按最终展开宽度与可用高度排版，外层面板仅负责裁切和形状动画；展开前即可确定是否需要滚动条，不因动画过程中的临时小尺寸而出现滚动条。测量与实际排版使用相同滚动条预留空间，内容放得下时不出现滚动条；
- 目录按钮、恢复自动宽度、拖动分隔线和关闭操作均提供本地化无障碍名称；支持Escape关闭和`prefers-reduced-motion`。

## 15. 图片、图标与资源

### 15.1 图片

- 首页不使用无意义大幅插画；
- 项目截图必须服务于功能说明；
- 优先使用 WebP、AVIF 或合理压缩的 PNG；
- 明确宽高，减少布局跳动；
- 为有信息价值的图片提供准确替代文本；
- 装饰图片使用空 `alt`；
- GIF 需要控制体积，并考虑减少动态效果场景。

### 15.2 图标

- 优先使用简洁 SVG；
- 视觉语言保持一致；
- 不直接复制受限制的 Apple 专有图标资产；
- 图标按钮必须有 `aria-label`；
- 重要信息不能只依靠图标表达。

## 16. 无障碍规范

必须满足：

- 使用语义化 HTML；
- 顶部导航使用 `<nav>`；
- 主内容使用 `<main>`；
- 每页只有一个主要 `<h1>`；
- 标题层级不无故跳跃；
- 所有功能支持键盘访问；
- 有清晰 `focus-visible`；
- 图标按钮具有可理解的动态标签；
- 图片具有合适 `alt`；
- 颜色不是唯一状态提示；
- 顶部工具按钮的命中区域为 44×44px，具体控件尺寸见各组件说明；
- 支持 `prefers-reduced-motion`；
- 支持 `prefers-color-scheme`；
- 每个语言路由输出正确的 HTML 语言属性；
- 外部链接在上下文中能够被识别；
- 页面缩放 200% 后仍可使用；
- 手机端无页面级横向滚动。

## 17. 内容语言与文案

### 17.1 中文

- 清楚、自然、直接；
- 不使用企业营销式口号；
- 不虚构用户量、收入、客户和性能指标；
- 技术内容说明背景、边界、实现和限制；
- 标题准确表达文章主题；
- 避免无意义的专有名词和强行造词。

### 17.2 英文

- 使用自然、简洁的技术英语；
- 标题可使用 Title Case，正文使用 sentence case；
- 操作名称优先使用动词加对象；
- 错误信息说明发生了什么以及下一步如何处理；
- 不使用空泛的营销最高级表达。

### 17.3 三语言一致性

- 简体中文、台湾繁体和英文表达含义一致，不要求逐字直译；
- 日期、阅读时间和无障碍标签按语言本地化；
- 三种语言的信息层级和稳定字段保持一致；
- 同一 slug 的三语言内容文件必须同时存在。

### 17.4 页面分享元数据

- 生产站点基准地址固定为 `https://steeefanie.top`，所有页面输出与当前路径一致的 canonical URL，不包含查询参数、片段或本地开发地址；
- 首页、栏目列表页和在线服务页使用 `website` 类型，随笔、项目和食谱详情页使用 `article` 类型；
- 所有页面统一输出当前语言的 Open Graph 与 Twitter/X Card 标题、描述、规范地址和语言标识；
- 三种语言页面分别输出自身 canonical，并互相输出 `hreflang="zh-CN"`、`zh-TW`、`en`；三种主页的 `x-default` 指向裸域语言入口，其他内容的 `x-default` 指向对应的简体中文页面；

## 20. 留言与评论

### 20.1 主页留言

- Contact 区使用44×44px细线留言图标作为入口，不增加顶部一级导航；
- 留言采用原生 `<dialog>`，桌面端四周保留18—32px页面间距，移动端保留8px及安全区；
- 桌面端使用信息侧栏与单列留言流，960px以下改为单列纵向布局；
- 打开后顶部控制层以常规滚动显隐的相同速度向上收起，关闭时以相同速度返回；同时锁定背景滚动，留言窗口内部独立滚动；
- 仅允许左上角关闭按钮和 Escape 关闭，关闭后恢复原滚动位置与入口焦点；
- giscus 在首次打开时加载，关闭后保留 iframe。

### 20.2 详情页评论

- 随笔、项目和食谱详情页均在上一篇/下一篇之后显示评论；
- 项目详情页沿用其他内容类型的发布日期顺序提供上一篇/下一篇；
- 评论区属于正文排版体系，使用顶部分隔线，不使用毛玻璃卡片；
- 三种语言使用不同 pathname，但以去除语言前缀后的逻辑路径作为稳定讨论标识，共用同一 Discussion；评论默认最新优先。

### 20.3 主题、语言与可访问性

- giscus 使用与本站令牌对应的浅色、深色自定义主题，并随站点主题即时更新；
- giscus 在各语言页面首次加载时直接使用对应的 `zh-CN`、`zh-TW` 或 `en` 界面语言；
- 留言入口、关闭按钮必须具有随语言变化的 accessible name；
- dialog 使用标题和说明关联、原生模态语义、焦点进入与恢复，并遵循 `prefers-reduced-motion`。

## 21. 规范维护

- 本文件只记录已实现且仍在使用的设计规则；废弃方案和待办计划不写入正文；
- `src/styles/tokens.css` 是运行时代码中的颜色与基础令牌来源；
- 组件不得私自新增重复颜色、字体或动效常量；
- 实现调整时同步更新对应文档段落，数值和组件行为与代码保持一致；
- 仅影响单个内容页面的特殊排版不应上升为全局令牌；
- 设计规范发生实质变化时更新版本和日期；
- 所有修改仍以内容可读性、可访问性和长期维护成本为最终判断标准。
