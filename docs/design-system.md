# Steeefanie Personal Site 设计规范

> 版本：3.1
> 状态：现行设计说明
> 更新日期：2026-11-01
> 适用范围：主页、随笔、项目、食谱、长文详情页及轻量工具页面

## 1. 文档定位

本文件记录 Steeefanie Personal Site 当前已实现的视觉、排版、布局、组件、交互、响应式和可访问性规则。项目与食谱的公开路由、页面目录和内容集合分别使用 `projects`、`recipes`。运行时数值以代码为准，文档随实现同步更新。3.0 采用接近 Apple 系统界面的圆角、悬浮控制层和分组表面，保留现有主题色、字体、内容及业务流程。本站是网页实现，不是 Apple 原生 Liquid Glass。

规范综合参考：

- Geist 的令牌化方法、排版尺度、4px 间距体系和克制的开发者界面风格；
- Apple Human Interface Guidelines 的层级、协调、一致性、适配、触控、动效和可访问性原则；
- 本项目“个人开发者主页 + 技术博客 + 项目案例”的实际信息架构；
- 当前 Astro、Markdown / MDX、三语言切换、搜索筛选和深浅主题实现。

参考内容用于排版、间距、组件状态和可访问性设计。

## 2. 设计目标

### 2.1 产品定位

网站首先是内容载体，其次才是个人品牌展示。核心目标是让访问者快速完成以下任务：

1. 了解 Steeefanie 的关注方向；
2. 浏览技术随笔和开发记录；
3. 查看项目背景、实现过程和使用方法；
4. 查阅菜谱、鸡尾酒配方和制作备注；
5. 在简体中文、台湾繁体、英文、深浅主题和不同设备间获得一致体验。

### 2.2 体验关键词

- 现代；
- 克制；
- 安静；
- 清晰；
- 内容优先；
- 技术感适度；
- 可长期维护。

### 2.3 核心原则

#### 内容优先

标题、摘要、正文和项目说明是视觉中心。装饰、插画、动效和容器不得压过内容。

#### 层级明确

全站文字共用 `--font-size-unit` 响应式基准：宽屏为 1rem，窄屏平滑缩至最低 0.94rem；固定字号按该基准设置比例，页面标题与正文二至四级标题另设连续缩放范围，始终保持字号层级。正文、简介、标签、导航、目录、搜索、图标名称、代码和工具页文字均纳入，使用 em 或 inherit 的子级随父级缩放。根字号和布局用 rem 不随这项规则改变。

通过字号、字重、间距、对齐和明度建立层级。颜色仅作为辅助，不单独承担状态表达。

#### 控制层与内容层分离

导航、语言切换和主题切换属于控制层，可以使用半透明和模糊；文章、项目和正文属于内容层，使用稳定背景，不使用大面积玻璃效果。

#### 一致而非完全相同

主页、随笔、项目和食谱共享基础视觉语言，但允许根据内容类型形成适当差异。随笔强调连续阅读，项目强调技术标签和实现过程，食谱强调材料、步骤、用时和份量。

#### 适配优先

布局必须适应屏幕宽度、字体缩放、语言长度和输入方式变化，而不是只适配某个设备截图。

#### 可访问性默认开启

键盘操作、焦点样式、减少动态效果、语义 HTML、合理对比度和足够大的触控区域贯穿现有页面和组件。

## 3. 品牌与颜色

### 3.1 不可变品牌基准色

标准品牌色固定为：

```text
RGB: 99, 6, 95
HEX: #63065F
```

浅色主题的品牌色为 `#63065F`，深色主题为 `#C979C4`。

品牌基准色主要用于：

- `Steeefanie` 站点名称；
- 重要品牌标记；
- 浅色背景上的链接和当前导航；
- 主要操作的实色背景；
- 少量标签、代码强调和装饰细节。

### 3.2 主品牌色与深色备用品牌色

浅色主题使用主品牌色；深色主题使用为可读性设定的备用品牌色。每种主题内部只允许一个紫色色值：

```css
:root {
  --brand: #63065f;
  --brand-interactive: #63065f;
  --brand-readable: #63065f;
  --brand-strong: #63065f;
  --brand-soft: rgba(99, 6, 95, 0.1);
  --focus: #63065f;
}

:root[data-theme='dark'] {
  --brand: #c979c4;
  --brand-interactive: #c979c4;
  --brand-readable: #c979c4;
  --brand-strong: #c979c4;
  --brand-soft: rgba(201, 121, 196, 0.16);
  --focus: #c979c4;
}
```

使用规则：

- 浅色主题中，任何紫色文字、图标、下划线、焦点环和状态标记都严格使用 `#63065F`；
- 深色主题切换时，上述所有品牌与交互用途全局替换为备用色 `#C979C4`，不得混用主品牌色；
- 需要弱背景时，只能以当前主题生效的品牌色增加透明度，不建立新的实色紫色；
- 大面积品牌实色按钮使用当前主题的 `--brand`，文字使用柔和的近白色；
- `#C979C4` 与深色页面、普通表面和抬升表面的对比度均达到普通文字WCAG AA底线；当前状态仍应同时使用下划线、字重、圆点或 `aria-current` 等非颜色信号。

品牌图标使用同一中心对称 S 形标志：浅色主题固定为 `#63065F`，深色主题固定为 `#C979C4`。标签页图标和导航字标只使用透明底版本，并跟随网站实际主题而不是仅跟随操作系统主题。

### 3.3 浅色主题

浅色主题使用不带色相倾向的中性灰。页面底色为浅灰，内容表面和顶部导航可使用纯白；品牌紫色不得混入页面、表面、代码块或导航底色。

```css
:root {
  --page: #f5f5f5;
  --surface: #ffffff;
  --surface-raised: #ececec;
  --surface-soft: #f3f3f3;
  --text: #222222;
  --muted: #888888;
  --border: #d9d9d9;
  --code-bg: #f0f0f0;
  --code-text: #000000;
  --header-bg: rgba(255, 255, 255, 0.64);
  --focus: #63065f;
}
```

### 3.4 深色主题

深色主题同样使用无色相倾向的中性灰，不使用大面积纯黑。页面保持深灰，导航公共层使用半透明深灰，与页面保持可辨识的层次。

```css
:root[data-theme='dark'] {
  --page: #111111;
  --surface: #1d1d1d;
  --surface-raised: #262626;
  --surface-soft: #1a1a1a;
  --text: #eeeeee;
  --muted: #888888;
  --border: #333333;
  --code-bg: #1e1e1e;
  --code-text: #d4d4d4;
  --header-bg: rgba(8, 8, 8, 0.64);
  --brand: #c979c4;
  --focus: #c979c4;
}
```

深浅主题不是简单反相。每个主题分别保证文字、边框、代码块和控制层具有稳定层次。

辅助文字沿用上次发布的浅深主题统一`#888888`。玻璃材质不得改写全站正文与辅助文字令牌，也不得用公共按钮颜色覆盖联系方式、移除、工具辅助操作及原有链接颜色。已确认的选中、悬停和禁用状态单独保留。

### 3.5 当前颜色对比度

下表按现行令牌计算，列出页面底色上的文字组合：

| 前景与背景 | 对比度 | 当前用途 |
|---|---:|---|
| `#222222` / `#F5F5F5` | 14.59:1 | 浅色正文 |
| `#888888` / `#F5F5F5` | 3.25:1 | 浅色辅助文字 |
| `#63065F` / `#F5F5F5` | 11.19:1 | 浅色品牌文字 |
| `#EEEEEE` / `#111111` | 16.28:1 | 深色正文 |
| `#888888` / `#111111` | 5.33:1 | 深色辅助文字 |
| `#C979C4` / `#111111` | 6.31:1 | 深色页面品牌文字 |
| `#C979C4` / `#1D1D1D` | 5.63:1 | 深色普通表面品牌文字 |
| `#C979C4` / `#262626` | 5.06:1 | 深色抬升表面品牌文字 |

焦点、当前状态和错误信息同时使用语义属性或形态表达。

### 3.6 状态颜色

当前站点以阅读为主，不建立大量彩色状态体系。项目不区分“已发布、实验、进行中”等状态，也不显示状态圆点；导航当前项、语言选择、筛选选中等交互状态必须同时依靠语义属性或形态变化表达，不能只依靠颜色。

## 4. 字体与排版

### 4.1 字体栈

```css
--font-sans-en: "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI", Arial, sans-serif;
--font-sans-zh: "Inter", "Noto Sans SC", "Source Han Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif;
--font-sans-zh-tw: "Inter", "Noto Sans TC", "Source Han Sans TC", "PingFang TC", "Microsoft JhengHei", sans-serif;
--font-mono: "JetBrains Mono", "SFMono-Regular", Consolas, monospace;
```

规则：

- 中文和英文正文均使用无衬线字体；
- Inter、Noto Sans SC、Noto Sans TC 使用 `public/fonts/site/` 内自托管的可变 WOFF2 字体和官方 Unicode 分片，保留各自 OFL 授权文件；运行时不依赖字体 CDN。中文页面的拉丁字母和数字优先使用 Inter，汉字按页面语言选择 SC 或 TC。仅接入字体，不修改既有字号、字重、行高和间距；留言主题同步使用该字库，正式 giscus 跨域字体请求需要部署文档中的字体 CORS 规则；
- 每种语言只使用一套主字体栈；
- 代码和等宽数据使用 `--font-mono`；
- 标签的拉丁字符优先使用等宽字体；简体中文标签必须在通用 `monospace` 之前回退到 `Noto Sans SC / Source Han Sans SC / PingFang SC / Microsoft YaHei`，台湾繁体对应回退到 `Noto Sans TC / Source Han Sans TC / PingFang TC / Microsoft JhengHei`，避免 Windows 因 Consolas 缺少中文字形而落入宋体；
- 在线字体加载失败时必须有可靠系统回退。

### 4.2 字重

界面主要使用三档字重：

```text
400 Regular：正文、摘要、说明
500 Medium：导航、标签、次级标题、按钮
600 Semibold：页面标题、章节标题、重点内容
```

### 4.3 排版令牌

字号以 `U = var(--font-size-unit)` 为基准，`U = clamp(0.94rem, 0.92rem + 0.1vw, 1rem)`。以下为当前使用的字号和行高：

| 样式／令牌 | 字号 | 行高 | 用途 |
|---|---|---|---|
| `--font-size-home-display` | `clamp(2.7U, 2.2U + 2.2vw, 4U)` | 1.06 | 首页主标题 |
| `--font-size-home-section-title` | `clamp(1.35U, 2.4vw, 1.85U)` | 1.25 | 首页区块标题；留言标题行高 1.2 |
| `--font-size-section-title` | `clamp(1.55U, 3vw, 2.2U)` | 1.25 | 内容详情标题；工具页标题行高 1.2 |
| `--font-size-prose-h2` | `clamp(1.3U, 2.35vw, 1.72U)` | 1.3 | 正文二级标题；评论标题行高 1.2 |
| `--font-size-prose-h3` | `clamp(1.15U, 1.85vw, 1.35U)` | 1.3 | 正文三级标题 |
| `--font-size-prose-h4` | `clamp(1.05U, 1.5vw, 1.12U)` | 1.3 | 正文四级标题 |
| `.prose` | `1.02U` | 1.72；英文 1.66 | 长文正文 |
| `.article-deck` | `1.08U` | 1.62 | 详情简介 |
| `.article-meta` | `0.78U` | 1.62 | 详情日期、类别、用时、份量和标签 |
| `.item-title` | `clamp(1.25U, 2.2vw, 1.72U)` | 1.25 | 内容列表名称 |
| 食谱图标视图名称 | `1U` | 1.5 | 图标下方名称 |
| `.prose pre` | `0.86U` | 1.55 | 代码块 |

`U` 是排版说明中的简写，代码使用 `calc(var(--font-size-unit) * 比例)`。普通标签、按钮、目录和工具页说明均以相同比例基准设置字号；使用 `em` 或 `inherit` 的文字跟随父级。根字号和布局用的 `rem` 保持独立。

大标题字距允许收紧，正文不使用负字距：

```text
home-display（英文）：-0.04em
home-display（中文混排）：-0.025em
home-section-title / article-title：-0.035em
正文二至四级标题：-0.028em
正文与元信息：normal
```

负字距不是装饰效果，也不应普遍用于正文。大号拉丁字母的字偶间距和字形两侧留白会随字号同步放大，保持默认字距时容易显得松散，因此展示标题允许轻微收紧，以恢复词形整体性和稳定的视觉密度。中文方块字本身占据较完整的字面空间，只需更弱的负字距；中英文混排不得直接套用强拉丁字距，否则中文笔画和标点会显得拥挤。字距必须随字号和文字系统分别校准，正文、摘要与元信息保持正常字距。

随笔、项目、家常菜和面食详情的顶层正文段落使用固定 `text-indent: 2rem`。鸡尾酒详情普通段落、页面导语、摘要、列表、标题、引用、图注、控件及表格无首行缩进。

主页介绍及“关于我”正文左对齐；随笔、项目、食谱详情页中的正文段落保持两端对齐，末行左对齐。中文使用字符间调整，英文使用词间调整并按当前 `lang` 启用自动断词；标题、摘要、列表说明、元信息、按钮和代码块不使用两端对齐。

### 4.4 阅读宽度

- 全站宽容器：1120px；
- 文章正文：680–740px；
- 中文正文优先保持较短行长；
- 英文正文建议每行约 60–80 个字符；
- 代码块和表格可在正文容器内部横向滚动，不扩大页面宽度。

### 4.5 文本缩放

布局必须在以下情况下保持可读：

- 浏览器缩放 200%；
- 320px 窄屏；
- 中英文长标题；
- 系统较大字体；
- 日期和标签长度增加。

重要内容不得通过固定高度裁切。导航和控件不得因文字变长而互相覆盖。

## 5. 间距体系

### 5.1 基础尺度

采用 4px 基础单位：

```text
space-1   4px
space-2   8px
space-3  12px
space-4  16px
space-6  24px
space-8  32px
space-10 40px
space-12 48px
space-16 64px
space-20 80px
space-24 96px
```

所有新增间距原则上从该尺度选择。确有排版需要时可以使用其他 4px 倍数，但不新增 17px、27px、42px、54px 等缺少体系依据的值。

### 5.2 使用节奏

- 4–8px：图标与文字、同组元信息。
- 12–16px：控件间距、标题与摘要。
- 24–32px：内容卡片内边距和列表条目。
- 40–64px：页面标题区与首页区块。
- 首页欢迎区桌面采用左右双列；800px 及以下改为单列。工具卡片桌面三列，600px 及以下单列。
- 连续列表桌面采用正文和元信息两列，条目内边距 28px 32px；800px 及以下单列、24px 内边距；360px 及以下缩至 20px。
- 分组列表、项目卡片与工具卡片均使用稳定表面，悬浮层使用独立材质。

## 6. 布局与响应式

### 6.1 容器

```css
--content-wide: 1120px;
--content-reading: 740px;
--page-gutter: 30px;
```

页面内边距：

```text
桌面：左右各30px
平板：左右各30px
手机（760px及以下）：左右各20px
```

宽容器和阅读容器共用视口边距。卡片可以有独立内部留白，但不得再包一层同样的页面边距。

### 6.2 项目断点

为保持与现有实现一致，使用以下行为断点：

```text
Compact：≤ 760px
Medium：761–800px
Wide：> 800px
```

断点用于内容需要发生变化的位置，不按具体设备型号增加断点。

验收视口至少包括：

```text
320×568
390×844
768×1024
1024×768
1440×900
```

### 6.3 对齐

- 导航内容与页面宽容器使用同一左右基准；
- 正文详情页使用独立阅读容器；
- 随笔、项目及主页最近更新列表使用单一内容区，日期、阅读时长和标签排列在摘要下方，按宽度自然换行；
- 移动端改为单列，元信息左对齐；
- 不使用无意义的居中对齐长正文；
- 三语言切换后整体基线和导航宽度保持稳定；四个导航项与搜索、主题按钮使用44px控制高度，公共玻璃外框高56px。导航、工具组及独立菜单按钮之间固定12px间距，不在窄屏断点覆写为2px或6px，避免生产CSS加载顺序与开发预览不同造成间距差异。语言地球按钮移至页脚版权行最右端，保持44px命中区域和19px图标，与版权文字同色，无底色。
- `Steeefanie` 是固定拉丁字标，其中首字母 `S` 由透明底品牌 SVG 替代，后续文字固定为 `teeefanie`。标志使用16.5×24px可见裁切框、27×27px居中图像，后续文字左外边距为-2px；完整链接的无障碍名称仍为 `Steeefanie`。文字统一使用拉丁字体栈、1 倍响应式字号基准、600 字重和 1 倍行高，不继承中文语言字体栈，随全站字号基准缩放。

### 6.4 首页布局

首页顺序保持欢迎语、个人介绍与联系方式、在线服务、最近更新、页脚。主标题桌面最大 5.25rem，随视口缩放；正文保留原三语言内容。

在线服务恢复重绘前的应用图标入口：桌面使用72px图标、104px列宽，名称置于图标下方居中，不显示重绘新增的说明文字；520px及以下恢复原有四列网格和自适应图标尺寸。关于我恢复重绘前的浅底说明块及原有间距。最近更新仍从随笔、项目、食谱各取最新一条，按发布日期排序，使用无外框列表。区块标题不再使用左侧装饰竖线。

### 6.5 随笔布局

不显示重绘新增的大号栏目标题及说明，仅保留供辅助技术使用的h1；采用开放列表与条目留白，不设置外框、底色和阴影。不增加标签筛选，保留分页、元信息、阅读时长与返回位置恢复。

### 6.6 项目布局

### 8.2 材质与液态玻璃

Chromium 材质以固定版本Hyalite 0.5.0的[官方Use、Options、Corners与Gotchas说明](https://github.com/VII-Cae/hyalite--liquid-glass/blob/b9f27192a7256bf5295bf027b582b86864f9b59d/README.md)为该引擎的实现依据。源提交为 `b9f27192a7256bf5295bf027b582b86864f9b59d`，源码与MIT声明保存在 `public/vendor/hyalite/`，无修改且不使用运行时CDN。

导航、工具图标组、分类栏、食谱视图切换及目录的独立背景复用同一套增强材质；取消原先两处的硬限制，按标记启用增强；搜索弹窗及确认弹窗也复用同一套折射，关闭后释放。折射几何、厚度、斜率和色散沿用Hyalite默认值；图标及一级小控件模糊为2px，菜单、展开目录、搜索及弹窗为3px，入场动画为0。深浅主题共用shade: 0.18、edgeW: 2，将暗部和光泽限制在相同的窄边缘。深色沿用已确认的浅色折射、色散、模糊、光照方向和边缘明暗范围，适配反光亮度：浅色保留rim: 1.76、edge: 0.32；深色使用rim: 0.35、edge: 0.03，同时降低滤镜内部白色反光与外侧CSS亮线，避免连续白色描边。浅色保留默认sat: 0.86；深色使用官方sat: 1旁路关闭可选的边缘降饱和合成，避免该遮罩在均匀暗底上产生细微横竖亮度条带，不改变位移、色散、模糊或高光参数。主体染色、控件及前景颜色由CSS切换；主题切换通过Hyalite.setOpts更新rim、edge和sat，不重新附着，不修改位移或色散。

CSS按官方接入示例，只消费附着元素本身的 `--hyalite` 和 `--hyalite-edge`：`backdrop-filter: var(--hyalite, blur(var(--glass-blur, 2px)))`、`box-shadow: var(--hyalite-edge, var(--glass-selection-shadow))`，另将中性染色覆盖在折射上方：浅色为13%不透明度白色；深色小面积模块使用55%不透明度的中性灰rgb(32 32 32)，滑块单独使用38%不透明度黑色遮罩；模块较亮、滑块较暗，交换先前近黑底材与亮滑块的深浅关系。大面板继续使用较高不透明度的--glass-bg保证可读。薄染色由--glass-tint控制主体色调，不用提高白色不透明度掩盖边缘暗带。材质分层为：背景折射与2px（一级）／3px（二级）模糊、Hyalite边缘明暗、薄染色、独立的中性选中滑块、清晰的文字和图标；滑块保留灰色中性遮罩，仅确认选中的文字采用主题色。导航与目录没有额外CSS描边、内高光、投影、饱和度滤镜或增强后不同的背景染色。工具图标组与导航一样使用独立Hyalite背景，不添加选择滑块；搜索和主题始终只显示公共玻璃底，悬停、键盘聚焦、按下及展开状态仅将图标改为主题色，不显示独立圆形底色或高光。语言选项的状态底色同样为中性遮罩，仅当前语言文字使用主题色。分类栏与食谱视图切换也使用独立Hyalite背景；控件文字和图标不参与滤镜，视图切换与导航共用selection-slider脚本和中性滑块。搜索弹窗通过data-glass="search"复用相同折射与边缘高光，保留高不透明度填色及搜索交互；正文保持稳定背景。

网站保持纯色背景，未使用的动态背景实验样式已清理。

液态玻璃重绘不额外添加装饰性分隔线：首页介绍、内容列表、相邻文章导航及页脚恢复重绘前相应的容器和间距样式，移除重绘新增的线条与对应留白。移动服务入口不添加分隔线。核对旧版后保留问卷原有的题目底线与题目间距，不将既有线条一并删除；输入框、焦点、表格、目录拖动手柄和正文既有语义样式继续保留。

公共材质通过`glass-surface`类复用，统一薄染色、2px模糊和Hyalite变量消费规则。导航背景、目录、分类筛选和食谱视图切换使用基础类；搜索、留言板及问卷确认弹窗另加`glass-surface--panel`，以较高不透明度和轻投影保证内容可读，不叠加额外亮边；语言与移动导航菜单使用`glass-menu`和独立的Hyalite背景，沿用小控件染色与光学参数，内部`menu-choice-group`复用唯一的中性选择滑块和悬停预览行为，入场缩放结束后重新测量滑块。菜单显示后在MutationObserver回调中立即接入折射，不等待300ms尺寸稳定计时；已有背景不重复附着，后续尺寸刷新仍合并处理。Hyalite读取不受缩放影响的布局尺寸，无需等待入场动画。关闭时不对菜单共同父容器应用opacity淡化，父层仅位移并收起投影；玻璃背景和文字层分别淡出，避免祖先透明度隔离背景采样后出现黑闪。公共类不会自动启用折射；通过独立背景层显式标记`data-glass="navigation"`、`data-glass="control"`、`data-glass="menu"`、`data-glass="contents"`或确认弹窗的`data-glass="dialog"`启用Hyalite，控件背景与内容分层。导航与图标组随局部路由持续保留；页面分类、视图切换和目录在离页时释放。实色及强制颜色回退覆盖所有公共材质实例。

滑块顶部内高光单独适配主题：浅色白色透明度80%，深色保留12%；外投影保持原值，不增加整圈描边或改变玻璃光学参数。胶囊外框与选择滑块使用相同的普通圆弧轮廓，不混用超椭圆。标准外框高56px；浅色滑块高44px、内缩6px，圆弧半径分别为28px和22px。深色单独向外补偿1px，滑块高46px、内缩5px，内圆弧半径23px；两种主题在端部均保持同心。滑块定位使用getBoundingClientRect保留亚像素尺寸，并计入滚动和边框偏移，避免offsetWidth／offsetLeft整数取整造成端部约1px的圆心偏差。

Hyalite按普通圆角矩形构建距离场，玻璃轮廓使用相同的普通圆角，不再叠加超椭圆裁切，避免轮廓与折射采样几何不一致。其 `shape: squircle` 描述的是斜面截面，不等同于CSS轮廓的超椭圆。库默认可能产生自身的亮暗边缘和折叠折射；不承诺只有一根亮线。

导航隐藏、搜索面板展开、目录拖动或页面不可见时解除相应增强；宽窄屏目录面板均复用菜单的相同折射、2px模糊与染色，关闭时仅保留可见入口的增强；语言与移动导航菜单使用独立小面积增强背景，展开时保留导航现有折射及高光，几何变化稳定后刷新。局部页面切换保留上栏和SVG滤镜定义，正文目录按页面重建。没有背景截图、WebGL或应用层持续逐帧循环。

Chromium支持时运行库的SVG背景滤镜；其他引擎和脚本失败时保留CSS模糊回退。减少透明度、增加对比度时使用实色并禁用增强；强制颜色模式使用系统色。没有背景滤镜支持时恢复实色。留言弹窗通过data-glass="dialog"复用搜索及确认弹窗的折射、3px模糊和边缘高光，打开时立即接入，关闭及离页时释放；保留现有文字排版、评论加载及原生dialog语义，上栏保持可操作，其余引擎使用相同CSS回退。

拼豆工具的固定宽／高和颜色模式各共用一个`radio-slider-group`滑块，通过原生单选输入的change事件更新，沿用导航滑块的指针预览、确认选中、主题色和深色5px间距。组底使用普通玻璃染色，只有唯一滑块使用较深遮罩；均不启用折射。两组外框及尺寸输入框为56px高胶囊，内部选项44px高，颜色模式在窄屏仍保持四项一行，仅显示本地化名称，不显示CM、CMS等缩写；预览标题旁也不显示模式缩写，生成请求仍保留原模式值。“生成图纸”按钮只显示居中文字，不带箭头；未上传图片时保留disabled状态，文字使用75%不透明度的--muted，控件本身保持不透明，不淡化玻璃底和高光。

固定玻璃按钮通过 `controls.css` 统一使用文章翻页箭头的 `--glass-tint` 底色和高光，不附着Hyalite。较深的 `--glass-selection-bg` 仅供唯一移动滑块使用，不用于固定按钮、选项或搜索结果状态。在线体验、搜索关闭、工具操作、测试选项、分页及留言关闭按钮均沿用固定玻璃底色，选中或悬停不换成滑块底色。文章相邻导航仅显示内容标题与48px箭头圆形按钮；标题始终保持正文色，仅箭头在悬停、键盘聚焦和按下时显示主题色。开始测试按钮及两个测试页全部答题选项的底色、高光与文章翻页箭头一致，保留各自形状；测试选项选中后改用 `--control-hover` 中性色底，浅色为7%黑色、深色为10%白色，保留主题色文字和高光；未选中仍使用翻页箭头的玻璃底色。“在线体验”使用包住文字的固定玻璃胶囊。问卷“稍后继续”按钮为48px高胶囊、左右各20px内边距，与48px翻页箭头的垂直中心一致，不启用折射；问卷前后翻页使用纯箭头，最后提交切换为确认符号，均保留本地化无障碍名称。七宗罪图标的水平翻转已写入PNG，按可见轮廓居中，仅校正左右留白，保持原有垂直位置，不再使用CSS翻转或偏移。

### 8.3 滚动行为

首页介绍区在801px以上采用双列布局：右列最小宽度由联系方式整行内容决定，邮箱不换行、操作图标不压缩，优先收窄左侧介绍列；800px及以下继续沿用单列布局及极窄屏联系方式自然换行。

文章初次进入时，目录完成宽度、布局和字体测量后直接呈现自动展开或折叠的最终状态，不播放面板入场、图标变换和正文让位动画；计算完成前隐藏目录入口，避免先出现折叠按钮。用户手动展开、收起继续保留原有动效。

玻璃材质及其背景层级由`surfaces.css`统一定义；`global.css`的导航、浮层几何规则不得重复定义玻璃背景、滤镜及投影。`top-chrome-surface`固定为局部第0层，文字和图标位于第1层，玻璃不响应指针。已移除旧版第99层及24px/28px模糊规则，避免开发热更新或样式加载顺序变化时，背景盖到文字上；分类、视图切换、菜单和目录复用同一约束。正序与逆序加载样式均须保持文字清晰。

- 字标位于页面顶部并随正文滚走；右侧栏目组和工具组固定显示，滚动时不自动隐藏。
- 不再注册上栏滚动方向判断及对应逐帧更新。食谱分类采用CSS sticky：所有宽度均使用与右侧导航／工具组相同的吸顶高度，不设置手机端额外纵向偏移。手机端分类栏吸顶后按右侧工具组的实际位置收窄，组间保留12px间距，分类可横向滚动；未吸顶时恢复完整宽度。玻璃背景在独立外框，只有分类文字和滑块随内部滚动；宽度切换时将已选分类带入可视区。通过IntersectionObserver判断吸顶临界点，ResizeObserver更新可用宽度，不使用持续滚动绘制循环。视图切换随页面滚走。body横向溢出使用clip，避免创建阻止sticky的滚动容器。
- 正文锚点及目录定位保留顶部间距，避免被上栏遮挡。
- 留言板打开期间保留独立浮层及正文滚动锁定，上栏可操作。
- 搜索使用独立轻遮罩，语言、移动菜单与宽窄屏目录不压暗整页。

### 8.4 搜索面板

桌面搜索面板位于导航下方居中，最大宽800px，高度不超过640px及可用视口。760px及以下占据导航下方剩余空间，底部适配安全区。面板有可见关闭按钮，输入框采用16px圆角静态玻璃表面；自动聚焦不显示外框，通过Tab切换焦点时提供中性焦点轮廓。

搜索打开时锁定正文位置、将正文和页脚设为inert，并约束键盘焦点在搜索面板内；关闭恢复滚动、交互和触发按钮焦点。方向键、Enter、Escape逻辑保留。桌面和移动端均有独立滚动区域。

## 9. 控件与交互状态

### 9.1 命中区域

顶部搜索、语言、主题和移动菜单按钮的命中区域为 44×44px，图标视觉尺寸约 18–20px。食谱视图开关外框为106×54px，每个选项的按钮操作高度至少44px。

### 9.2 必备状态

触控交互通过 `input-modality` 模块记录真实指针类型：触摸时屏蔽浏览器残留的模拟悬停装饰，仅保留原生按下反馈、键盘焦点和真实选中状态；鼠标或笔重新移动后恢复悬停。局部路由切换保留输入方式，不使用强制失焦规避高亮。滑块在触摸按下或指针取消时清除临时预览，回到已确认选项。

触摸滑块通过 Pointer Events 拖动：超过8px且沿控件方向移动后进入预览，松手调用目标选项原有点击行为，仅确认后改变主题色；反向滚动、指针取消或在控件外松手恢复已选项，抑制拖动后重复的原生点击。横向组保留纵向滚动和双指缩放；纵向菜单与目录仅从当前滑块处开始拖动，其余条目保留纵向滚动。拖动期间禁用滑块过渡，横向溢出组在边缘移动时同步滚动。

Hyalite 未附着时，公共玻璃背景使用 `--glass-selection-shadow` 回退，保留与静态控件一致的 CSS 顶部高光和轻阴影，配合原有底色及2px模糊；不依赖折射脚本生成高光。Chromium 附着后仍优先使用 `--hyalite-edge`，不叠加额外边缘层。WebKit 加载失败与其他浏览器使用该回退，实际 iOS Safari 触控和显示仍需真机核验。


每个按钮和链接至少实现：

```text
default
hover
focus-visible
active / pressed
disabled（如适用）
current / selected（如适用）
```

状态规则：

- hover 只能作为辅助，功能不能依赖 hover；
- active 必须有即时反馈；内容列表不改变横向内边距、缩放或宽度，通过背景及标题颜色反馈，避免交互后重新换行；
- focus-visible 必须清晰可见；
- disabled 不响应操作，并提供视觉和语义状态；
- 桌面及移动导航的当前项使用品牌色文字、胶囊底与 `aria-current` 共同表达；不再绘制底部短线。
- 搜索、语言、主题和菜单图标按钮的悬停、聚焦与展开状态使用中性遮罩；图标保持当前主题的正文色；

### 9.3 确认弹窗

两个测试页的清除确认弹窗复用`confirmation-dialog`：宽度不超过420px，四周至少16px，28px圆角、24px内边距，采用较高不透明度的玻璃面板与3px模糊，通过data-glass="dialog"启用与导航相同的Hyalite折射；打开时立即接入，关闭或离页时释放，按钮本身保持无折射。标题与说明间距12px，说明与操作区间距24px；取消与确认按钮等宽、高48px，只有确认操作文字使用主题色。默认聚焦取消，保留原生模态焦点约束、Escape关闭与关闭后焦点恢复，并通过aria-describedby关联不可恢复的清除说明。减少动态效果时关闭入场动画，减少透明度或强制颜色时回退到实色。

### 9.4 焦点样式

当前公共焦点样式为：

- 语言类型固定为 `zh-CN | zh-TW | en`，URL 前缀分别为 `zh-cn`、`zh-tw` 和 `en`；

- 搜索结果、导航、上一篇/下一篇、在线工具和项目互链必须留在当前语言；不得因点击站内链接退回简体中文。

三语言通用界面文案集中维护；内容以同 slug 的三份文件配对，任一语言缺失时不进入正式列表、详情路由和搜索索引。

## 11. 主题切换

### 11.1 控件

- 使用太阳短射线与右下月相切口组合图标，使用代码内 SVG 绘制；
- 月相主体不得添加完整圆形描边；由右下方月牙的弧线、人眼视觉补齐和外围射线共同建立圆形感；
- 图标使用 `currentColor`，不得嵌入固定黑白位图或依赖主题背景色切口；
- 图标按钮具有动态 `aria-label`；
- 图标视觉尺寸约 18–20px；
- 按钮命中区域至少 44×44px。

### 11.2 初始化优先级

```text
1. localStorage 已保存主题
2. prefers-color-scheme
3. 浅色主题
```

主题初始化应在页面绘制前尽早执行，避免闪白或闪黑。

### 11.3 扩散动画

- 切换开始时必须完整保留旧主题，不得先将整个页面立即切换到新主题；
- 浏览器先捕获旧主题，再提交新主题状态；
- 新主题作为新视图，从当前可见主题图标的几何圆心以圆形裁剪区域逐渐显现；
- 圆扩散到哪里，哪里才显示新主题；圆外区域在动画完成前继续显示旧主题；
- 圆心必须读取 SVG 图标的实时边界中心，不使用整个 44px 按钮命中区域的中心代替；
- SVG 中心坐标必须换算为根视口宽高内的百分比，再传给圆形裁剪；不得直接把页面 CSS 像素作为快照伪元素的局部坐标，以免桌面快照发生缩放时圆心偏移；
- 半径覆盖最远视口角点；
- 覆盖半径与圆心百分比基于同一冻结根快照视口；宽度必须使用包含经典滚动条区域的 `window.innerWidth`，不得使用会少一个滚动条宽度的 `documentElement.clientWidth`；快照组固定宽高且 `transform: none`；
- 根元素使用 `scrollbar-gutter: stable` 稳定保留经典滚动条沟槽，避免 Windows Chrome 在快照层与真实页面之间出现横向抖动；
- 旧主题快照固定 `opacity: 1`、`filter: none`，不得参与淡出、压暗、缩放或透明度动画；仅裁剪新主题快照；
- 视觉节奏按半径匀速，使用 `r(t)=Rt` 的线性关键帧；时间25%、50%、75%时半径分别达到覆盖半径的25%、50%、75%；
- 总时长按覆盖半径计算为 `clamp(280ms, radius / 3.3, 440ms)`，手机保持快速，大屏增加有效帧数；
- 圆形裁剪动画必须预先声明在 `::view-transition-new(root)` 上，使其在新视图图层生成时同步启动；
- 不得先将 View Transition 动画全部置空，再等待 `transition.ready` 后通过 JavaScript补挂动画，以免首次加载时产生伪元素生命周期竞态；
- 根快照组允许关闭默认几何插值，但必须明确冻结其视口宽高和变换，不能让浏览器在新旧几何之间缩放；
- 优先使用 View Transitions API 保证背景、文字、边框和控件同步切换；
- 不支持 View Transitions 时降级为短暂淡出、提交主题、再淡入，不允许出现突兀闪白或闪黑；
- 不引发布局跳动；
- 快速连续点击必须加锁或合并；
- 不支持高级动画时降级为短暂渐变；
- 主题图标在扩散期间保持位置和姿态稳定，不叠加旋转动画；
- `prefers-reduced-motion: reduce` 时取消扩散。

该动画是主题状态变化反馈的特例，不作为其他页面大范围使用动画的依据。

## 12. 动效规范

### 12.1 时间令牌

```css
--motion-fast: 150ms;
--motion-standard: 200ms;
--motion-overlay: 300ms;
--motion-theme: 360ms; /* 动态时长的中间参考值 */
```

### 12.2 使用范围

| 场景 | 建议时长 |
|---|---:|
| 链接颜色、按钮背景 | 100–150ms |
| 按下反馈 | 100–140ms |
| 导航胶囊状态 | 150ms |
| 导航显隐 | 200–220ms |
| 普通浮层 | 200–300ms |
| 主题圆形扩散 | 280–440ms，半径线性 |

### 12.3 原则

- 动效用于说明状态、层级或操作结果；
- 除用户明确要求的慢速液态背景外，不添加持续循环的装饰动画；减少动态效果时背景保持静止；
- 不使用视差、大面积漂移和强烈弹跳；
- 不依赖动画传递唯一重要信息；
- 减少动态效果时优先使用颜色变化、淡入淡出或直接切换；
- 滚动监听使用被动监听和 `requestAnimationFrame`。

## 14. 长文排版

### 14.1 结构

Blog 详情页顺序：

```text
标题
摘要
日期 / 更新时间 / 标签 / 阅读时间
正文
上一篇 / 下一篇
```

详情标题必须读取内容 frontmatter 的 `title` 并由统一模板输出；Markdown / MDX 正文不得重复书写一级标题，也不得在单篇内容中覆盖标题字号。详情标题由原有全局样式与字号令牌统一设置响应式尺寸，和首页展示标题、区块标题保持独立层级。

### 14.2 正文

- 中文正文行高 1.72；
- 英文正文行高 1.66；
- 中英文正文段落均两端对齐且末行左对齐；英文启用自动断词，避免过大的词间空白；
- 随笔、项目、家常菜和面食的顶层正文段落使用固定 `2rem` 首行缩进；鸡尾酒正文、列表、引用、图注和表格无首行缩进；
- 有序列表必须显式使用十进制序号，无序列表必须显式恢复圆点，不能依赖浏览器在 CSS Reset 之前的默认样式；
- 标题层级必须连续、清晰；
- 段落之间通过间距区分；
- 链接使用品牌色和下划线；
- 引用使用细品牌色左边框；
- 表格在正文容器内水平居中，表格单元格文字居中且无首行缩进；超出阅读宽度时只在表格容器内部横向滚动；
- 图片必须有 `alt`；
- 大图避免阻塞首屏；正文图廊中的非首屏图片使用懒加载。

### 14.3 代码

- 使用等宽字体；
- 背景与正文形成清晰但柔和的层次；
- 横向溢出时只滚动代码块；
- 不使用过度花哨的语法主题；
- 行内代码与代码块有明确区别；Markdown / MDX 代码块由 Shiki 同时输出 VS Code 的 Light+（light-plus）与 Dark+（dark-plus）配色，跟随网站 data-theme 切换语法高亮；浅色代码背景为柔和浅灰 #f0f0f0，深色为 #1e1e1e，不依赖系统主题单独判断；
- 代码不得包含真实密钥、Token、密码或个人敏感路径。

### 14.4 文章目录

- 随笔和项目详情页在正文包含至少3个二级或三级标题时显示目录入口；食谱详情页不显示目录；
- 目录入口为48×48px玻璃圆形按钮，图标使用列表符号，展开时切换为关闭符号。覆盖模式入口固定在上栏最左端，同时隐藏字标；宽窄屏均保留独立按钮，矩形目录面板位于按钮下方，间距16px，不再将按钮并入面板标题行；
- 目录展开面板复用窄屏导航菜单的`glass-menu`背景与动效，背景和内容分层，200ms展开、160ms收起；关闭时背景与内容分别淡出，不对共同父层改变透明度。目录选项与菜单一样直接置于选择组内，移除中间列表项包装；条目在悬停、聚焦及选中时始终透明，只由唯一滑块绘制底色，避免静止悬停底与移动滑块叠加；条目与滑块沿用菜单的胶囊圆角，宽窄屏均使用与菜单相同的折射、3px模糊、染色及高光，展开时立即接入折射；不设置全页遮罩或背景压暗，不将正文设为inert；
- 主页“关于我”、在线服务图标、留言与GitHub圆形入口、翻页箭头、工具及问卷按钮共用静态玻璃底与高光，不使用背景模糊或折射；留言、GitHub及翻页箭头均为48px圆形；
- 并列目录左边界与Steeefanie字标左边界对齐，不固定与文章的间距，与窄屏目录及导航菜单共用玻璃材质；折叠判断沿用原算法：扣除目录宽度及两侧各16px预留后，仍能容纳原正文阅读宽度与两侧各30px留白时允许并列。目录入口初始顶部与字标底部相隔24px，手动收起后入口位于字标下方、与字标左对齐，随滚动上移至导航高度后限位。覆盖目录使用折射背景，展开面板位于入口下方；目录超过可用视口高度时在内部滚动；
- 目录收录二级、三级标题，三级标题使用缩进区分层级；未选中条目使用主要文字色，当前章节采用品牌色文字与唯一中性滑块，不显示左侧线条；滑块跟随指针预览，只有当前章节文字显示主题色；
- 展开时重新判断当前章节，并仅在目录内部滚动使当前条目可见；页面顶部不按页底处理，页面及字体加载完成后刷新当前章节；鼠标展开不强制移动焦点，键盘展开时聚焦当前章节；
- 展开后根据实时几何空间判断布局，不以触摸或鼠标输入类型判断：剩余区域能够容纳原正文阅读宽度及左右页边距时，整个文章区域移入右侧剩余空间并居中；空间不足时目录覆盖在页面上，文章位置保持不变；
- 点击章节后立即定位，不使用平滑滚动；覆盖模式在点击正文、滚动正文或选择章节时关闭目录，并列模式保留目录；进入文章时并列模式默认展开，覆盖模式默认收起；同一模式内保留本页用户的展开选择；视口或目录宽度变化时实时重新判断模式；
- 目录默认宽度依据当前语言标题的实际字体宽度计算。将标题宽度从短到长排序，按最近秩法取P80；最长标题不超过P80的1.2倍时按最长标题计算，否则按P80的1.2倍计算，再加固定内边距与层级空间，并限制在260—380px；
- 用户可通过面板右边缘使用鼠标、触控笔、触摸或键盘调整宽度，手动宽度限制在240—440px并本地保存；手动值优先于自动值，语言切换不覆盖；恢复自动宽度后重新按当前语言计算；
- 窄视口只临时压缩实际显示宽度，不覆盖用户保存的手动值，视口恢复后继续使用原值；
- 移动端地址栏伸缩等仅改变可视高度的 `resize` 不重新测量目录宽度，避免收起状态的圆形入口短暂横向展开；
- 初始化、字体加载、页面加载与恢复、宽度变化时，只测量目录内部列表，不临时改变圆形面板的宽高或位置；同时观察目录标题栏与列表的实际尺寸变化并重新计算高度，避免初始测量过早导致展开内容被裁切；
- 目录内部列表始终按最终展开宽度与可用高度排版，外层面板仅负责裁切和形状动画；展开前即可确定是否需要滚动条，不因动画过程中的临时小尺寸而出现滚动条。测量与实际排版使用相同滚动条预留空间，内容放得下时不出现滚动条；
- 目录按钮、恢复自动宽度、拖动分隔线和关闭操作均提供本地化无障碍名称；支持Escape关闭和`prefers-reduced-motion`。

## 15. 图片、图标与资源

### 15.1 图片

- 首页不使用无意义大幅插画；
- 项目截图必须服务于功能说明；
- 优先使用 WebP、AVIF 或合理压缩的 PNG；
- 明确宽高，减少布局跳动；
- 为有信息价值的图片提供准确替代文本；
- 装饰图片使用空 `alt`；
- GIF 需要控制体积，并考虑减少动态效果场景。

### 15.2 图标

- 优先使用简洁 SVG；
- 视觉语言保持一致；
- 不直接复制受限制的 Apple 专有图标资产；
- 图标按钮必须有 `aria-label`；
- 重要信息不能只依靠图标表达。

## 16. 无障碍规范

必须满足：

- 使用语义化 HTML；
- 顶部导航使用 `<nav>`；
- 主内容使用 `<main>`；
- 每页只有一个主要 `<h1>`；
- 标题层级不无故跳跃；
- 所有功能支持键盘访问；
- 有清晰 `focus-visible`；
- 图标按钮具有可理解的动态标签；
- 图片具有合适 `alt`；
- 颜色不是唯一状态提示；
- 顶部工具按钮的命中区域为 44×44px，具体控件尺寸见各组件说明；
- 支持 `prefers-reduced-motion`；
- 支持 `prefers-color-scheme`；
- 每个语言路由输出正确的 HTML 语言属性；
- 外部链接在上下文中能够被识别；
- 页面缩放 200% 后仍可使用；
- 手机端无页面级横向滚动。

## 17. 内容语言与文案

### 17.1 中文

- 清楚、自然、直接；
- 不使用企业营销式口号；
- 不虚构用户量、收入、客户和性能指标；
- 技术内容说明背景、边界、实现和限制；
- 标题准确表达文章主题；
- 避免无意义的专有名词和强行造词。

### 17.2 英文

- 使用自然、简洁的技术英语；
- 标题可使用 Title Case，正文使用 sentence case；
- 操作名称优先使用动词加对象；
- 错误信息说明发生了什么以及下一步如何处理；
- 不使用空泛的营销最高级表达。

### 17.3 三语言一致性

- 简体中文、台湾繁体和英文表达含义一致，不要求逐字直译；
- 日期、阅读时间和无障碍标签按语言本地化；
- 三种语言的信息层级和稳定字段保持一致；
- 同一 slug 的三语言内容文件必须同时存在。

### 17.4 页面分享元数据

- 生产站点基准地址固定为 `https://steeefanie.top`，所有页面输出与当前路径一致的 canonical URL，不包含查询参数、片段或本地开发地址；
- 首页、栏目列表页和在线服务页使用 `website` 类型，随笔、项目和食谱详情页使用 `article` 类型；
- 所有页面统一输出当前语言的 Open Graph 与 Twitter/X Card 标题、描述、规范地址和语言标识；
- 三种语言页面分别输出自身 canonical，并互相输出 `hreflang="zh-CN"`、`zh-TW`、`en`；三种主页的 `x-default` 指向裸域语言入口，其他内容的 `x-default` 指向对应的简体中文页面；

## 20. 留言与评论

### 20.1 主页留言

- Contact 区使用48×48px静态玻璃圆形细线留言图标作为入口，不增加顶部一级导航；
- 留言采用原生 `<dialog>` 的非模态显示方式：桌面宽度为`min(800px, 100% - 48px)`，水平居中、顶部位于上栏下方12px，底部距动态视口底部16px；760px及以下为上栏下方8px至动态视口底部的全宽面板，底部内边距保留安全区。搜索使用相同尺寸规则。弹窗与内部滚动容器使用明确高度，长评论在弹窗内滚动，不撑出视口；
- 留言内容采用单列，信息说明置于留言流上方；桌面24px、窄屏20px内边距，与搜索一致；保留原有字号、字色与说明段落间距；
- 打开后上栏保持显示并可操作，仅正文及页脚暂不接受交互；同时锁定背景滚动，留言窗口内部独立滚动。上栏搜索会先收起留言再打开搜索，导航菜单及主题切换可直接使用；
- 支持右上角关闭按钮和 Escape 关闭，按钮与搜索弹窗一致：桌面顶部及内容右侧各24px、760px及以下各20px，留言关闭按钮额外补偿实际滚动条宽度，与搜索按钮对齐；搜索标题沿用留言标题字号、字重及行高；关闭按钮使用44px独立圆形玻璃背景，接入现有色散引擎并使用2px模糊，叉图标位于材质层上方；不额外叠加矩形遮罩。弹窗材质使用独立背景兄弟层，正文、iframe及关闭按钮不位于背景滤镜元素内部，避免叠层合成产生矩形模糊块。关闭后恢复原滚动位置与入口焦点；切换搜索或页面时不抢回焦点；
- 留言与搜索收起统一为180ms纯透明度淡出，面板与遮罩同步；淡出期间保持面板尺寸与折射不变，不刷新正在收起的折射背景。结束后才隐藏面板、释放折射并解除滚动锁定，避免先撤销搜索展开状态引起高度跳变；
- giscus 在首次打开时加载，关闭后保留 iframe。
- 评论框、留言卡片、回复和操作按钮使用与站点固定按钮一致的中性透明底及高光，不启用折射或背景滤镜，不改动原有文字排版；外层留言弹窗保留既有折射。深浅自定义主题同步更新并通过版本参数刷新缓存。
- iframe创建后即显示嵌入区，由giscus继续渲染；不以尺寸通知作为显示前提。脚本失败、明确服务错误或12秒未创建iframe时显示错误提示和GitHub Discussions入口；超时后创建iframe可以恢复，明确服务错误后的尺寸消息不会抹掉错误提示。
- iframe画布保持透明，仅输入框、留言卡片和按钮使用静态玻璃底与高光。三语言字体从本站正式字体地址加载，本地主题编码保留CSS选择器空白；排序和输入框操作栏在窄屏允许换行，长正文可断行、代码块内部横向滚动。回复框以展开状态为几何基准：外层卡片24px圆角、径向留白12px，内框圆角由“外圆角减留白”计算为12px，使相邻内外圆弧同圆心；收起入口沿用同一套尺寸变量，聚焦及失焦不另改圆角，避免底角被外层裁切。收起入口与展开后失焦的回复框均高44px，文字内边距为上下10px、左右12px，行高24px；失焦时清除编辑区额外内边距，保持文字起点与基线一致。评论文字输入区与下方Markdown提示栏由同一个write容器绘制背景及圆角；聚焦时整块容器使用与“输入／预览”选中底相同的中性底色，圆角沿用回复框内圆角，清除giscus默认容器焦点外环，文本框不再单独叠加底色或圆角；强制颜色模式保留系统焦点标识。
- 开发预览可访问`/zh-cn/?comments-preview=1`并打开留言，使用真实自定义主题展示明确标注的模拟输入、预览、发送、回复和排序。示例数据仅存内存，不提交GitHub，刷新即清除；模拟分支不进入生产构建。
- “最早／最新”按正式giscus的列表项及aria-current标记实现单一滑块：悬停跟随、离开回到已选项，只有确认选中的文字采用主题色；字号0.82rem，按钮命中高度44px。滑块使用CSS伪元素，跨域嵌入无须注入脚本；深色沿用5px补偿。“撰写／预览”整体距编辑框顶部8px、左右12px，保留44px点击高度；选中底上下收进6px、左右收进4px，使用与站点分段控件一致的胶囊轮廓，实际高度32px、文字左右各留14px；文字大小不变。

### 浏览器材质策略与本地实验

Chromium 保留本地 Hyalite 0.5.0 原折射；WebKit 默认启用本地 simple-liquid-glass 5.6.0 WebGL 材质，其他引擎不启用折射。所有引擎保留高光、中性遮罩和阴影；加载失败恢复完整 CSS 材质。图标和一级小控件使用2px模糊，菜单、展开目录、搜索和弹窗使用3px；两种引擎的参数与 CSS 后备一致。纯色背景上的关于我、联系/GitHub、在线入口、翻页、工具及问卷按钮不设置 backdrop-filter，也不挂接折射。

WebGL 由 src/scripts/webgl-glass.ts 管理。按 data-glass 标记接入可见背景，关闭、隐藏或离页时释放；公共上栏仍保持原有局部导航机制。背景在浏览器本地分块缓存，预算24MiB，覆盖 main-content 内标题、摘要、标签、正文及页脚，不上传截图。缓存提供器增加可选 sections 选择器，避免把整个长文缩成单张图片；上游光学实现不变，补丁及 MIT 声明随 vendor 保存。较大浮层的内容位于装饰画布上方，WebGL 就绪时关闭后备底层绘制，只保留一套遮罩、高光及阴影。

窄屏食谱分类与视图切换同一行；分类可横向滑动，为右侧视图控件预留106px及12px间距。吸顶时仍遵循与上栏图标组避让的既有规则。

本地保留 ?webgl-glass=1 强制 WebGL 对照入口。已淘汰的内容滤镜、滚动副本和动态背景实验从运行代码及公共资源中移除，删除前备份到本地 output/archives/retired-glass-experiments-20261102.zip；历史 WebGL 检查点仍保留在 tmp/checkpoints。归档不提交。WebKit 真机表现仍需用户 iPhone 验证，桌面强制 WebGL 不替代真机验收。

### 纯色背景控件与美化代码清理

是否需要背景采样按实际位置与背景判定，不按 fixed 定位判定。关于我、联系与GitHub、在线服务入口、翻页、工具及问卷按钮保留遮罩与高光阴影，不设置 backdrop-filter，也不挂接 Hyalite/WebGL。宽屏停靠模式的目录图标位于正文外纯色留白，关闭模糊和折射；窄屏悬浮模式可能覆盖正文，保留2px模糊和当前引擎的折射。展开目录、菜单、搜索等大面板保持3px。两种增强引擎共用 glass-policy.ts 的静态背景判定及模糊规则，防止静态控件被重新接入。已清理旧 recipe-view-thumb 样式及重复目录标题规则；现用 selection-slider 不变。

### 生产样式加载顺序

所有页面通过 `src/styles/site.css` 统一加载基础样式、玻璃表面和控件样式，按 `global.css → surfaces.css → controls.css` 顺序处理。语言入口页也使用相同入口，避免构建提取共享基础样式后将其排在玻璃规则之后。食谱分类按钮与导航文字按钮统一为44px高，分类外框加上下各6px留白后为56px；按钮使用1倍行高与垂直居中，不由正文行高撑大。上栏各组只通过12px gap分隔，导航不额外添加右外边距。
